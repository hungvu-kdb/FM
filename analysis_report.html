Football Manager Portrait Frame — Analysis Report

Three independent formalizations of the same 260×310 transparent-border effect, fitted from the 46 samples in Root/. Generated 13 August 2026.

What was actually found

The "transparent border with a gradient" is not a per-image effect and not a blur of the portrait. It is a fixed alpha channel shared by every sample. The RGB data changes from player to player; the alpha channel essentially does not.

Mean per-pixel alpha std0.40across all 46 images
Max per-pixel alpha std25.70localised on the content edge

A standard deviation near zero at almost every pixel is the whole finding. It means one shared alpha field explains the data, and all three MVPs are therefore competing compressions of the same field, not competing theories about it.

Structure of that field

Scanning any line through the shared alpha reveals three concentric zones:

  1. Outer glow — a smooth alpha ramp from 0 up to about 98–100 over roughly 9 px, following the rounded outline. Its colour is pure black (0,0,0) in every single sample, so it is a drop shadow, not portrait content.
  2. Transparent gap — a band of alpha ≈ 0 that detaches the glow from the picture. This gap is what makes the glow read as a soft halo rather than a border.
  3. Content region — a hard-edged rounded rectangle at alpha 255, bounding box x ∈ [19,241], y ∈ [18,292], about 75.7 % of the frame.

How it was found

The same measurement pipeline underpins all three:

  1. Decode all 46 PNGs to straight (non-premultiplied) RGBA. The set is mixed: 31 files are palette-based with a tRNS transparency table, 15 are true RGBA. Palette indices must be expanded through the palette before the alpha means anything.
  2. Stack the alpha channels into an N×H×W array and compute per-pixel mean and standard deviation. The near-zero std is what licenses a shared model.
  3. Isolate the glow by masking pixels with 0 < alpha < 255 and averaging their RGB. Result ≈ (0.4, 0.4, 0.4), i.e. black.
  4. Fit a candidate representation to the mean field, then score it back against the 46 real alphas — not against the mean — so a model cannot score well by simply memorising its own fitting target.

On formalization

Every model shares the same compositing skeleton. Given a frame F and an input portrait P:

RGB_out(y,x) = RGB_P(y,x) where F is content = (0,0,0) elsewhere (the glow is black) A_out(y,x) = F(y,x) ⊗ source transparency

What differs between the MVPs is entirely how F is stored and reconstructed: as a literal matrix, as a geometric formula, or as a product of one-dimensional profiles. That choice drives file size, editability, and how gracefully the model generalises to other canvas sizes.

Which one should you use?

  • You just want your face in the game. MVP1. It reproduces the original frame most faithfully and takes one command.
  • You want to tweak the look — thicker halo, rounder corners, different gap. MVP2. Edit a number in model.json and re-render.
  • You want a different canvas size or a portable model. MVP2 for pure scalability; MVP3 if you want measured fidelity with no runtime dependencies at all.

What I found

MVP1 was the first pass, and it is where the central discovery was made: the alpha channel is a constant across the dataset. Stacking all 46 alpha channels and taking the per-pixel standard deviation gives:

Mean std0.40
P[std < 5]98.5 %
P[std < 1]87.7 %

With variance that low, the alpha is not a function of the portrait. It is a fixed template that the designer applied identically to every player. The "gradient effect" the user perceives is the soft black halo in that template.

Measured geometry:

  • Content bounding box x ∈ [19,241], y ∈ [18,292] — 60,998 px, 75.7 % of the frame.
  • Glow region — 9,601 px, 11.9 % of the frame.
  • Glow mean RGB ≈ (0.4, 0.4, 0.4), i.e. pure black at fractional alpha.

How I found it

  1. Loaded all 46 samples with Pillow, converting to RGBA so palette files and true-RGBA files became comparable.
  2. Built an N×310×260 NumPy array of alpha and reduced it with mean(axis=0) and std(axis=0). Saved both as greyscale previews — mean_alpha.png and std_alpha.png — because looking at the std image immediately shows the only disagreement is a one-pixel ring on the content edge.
  3. Took horizontal and vertical scanlines through the mean to read off the three zones numerically.
  4. Masked the partially transparent pixels and averaged their RGB to confirm the glow colour.
  5. Snapped the mean to clean values and froze it as template_alpha.npy.

Formalization

The template is the model. No parameters are inferred; the matrix is the parameter set.

T ≈ M (per-pixel mean alpha, snapped), T ∈ {0..255}^{310×260} Ω(y,x) = 1 ⇔ T(y,x) = 255 (binary content mask)

Applying the frame is then a single Hadamard product plus a channel swap:

O_RGB(y,x) = P(y,x) · Ω(y,x) O_A(y,x) = T(y,x) compactly: O = [ P ⊙ Ω ‖ T ]

Because Ω ⊙ Ω = Ω and the alpha is overwritten rather than multiplied, the operator is idempotent: framing an already-framed image changes nothing.

The --fit variant

Pixel-aligned mode clips whatever falls outside the rounded corners. --fit avoids that by scaling the portrait to cover the content box B = [19,241]×[18,292] (222×274) and centre-cropping first:

P' = CenterCrop_B( Resize_cover( P, B ) ) O = [ P' ⊙ Ω ‖ T ]

My solution

python MVP1\build_template.py                      # fit and freeze template_alpha.npy
python MVP1\apply_border.py INPUT OUTPUT          # pixel-aligned
python MVP1\apply_border.py INPUT OUTPUT --fit    # scale-to-cover + centre-crop

Roughly 20 lines of real work: load the .npy, derive content_mask = template == 255, resize the input to 260×310 if needed, zero the RGB outside the mask, then np.dstack([rgb, template]) and save as RGBA.

Trade-offs

  • Most accurate. It stores the ground truth, so nothing can beat it on the geometry it was fitted to.
  • Locked to 260×310. The model has no notion of shape, so it cannot be re-rendered at another size — only resampled.
  • Not editable. Want a thicker halo? There is no parameter to change; you would have to edit 80,600 numbers.
  • Bulky. 80,728 bytes of binary NumPy that a human cannot read or diff.

Libraries — and alternatives

What I used

  • NumPy — the array stacking, mean/std reductions, boolean masking, and dstack. This model is essentially four NumPy calls.
  • Pillow — PNG decode/encode, convert("RGBA") to normalise palette images, and LANCZOS resampling.

If you want to do the same thing differently

  • scikit-image — io.imread plus richer measurement helpers (regionprops, find_contours) if you want the content region extracted analytically rather than by thresholding.
  • OpenCV (opencv-python) — fastest option at scale and has cv2.merge / cv2.split for channel work. Watch the BGR channel order and note that IMREAD_UNCHANGED is required to keep alpha at all.
  • imageio — a thinner I/O layer than Pillow if all you want is "give me an array".
  • ImageMagick — no code needed for the apply step: magick input.png template.png -alpha off -compose CopyOpacity -composite out.png does the same compositing from a shell.
  • sharp (Node) or image-rs (Rust) — if you want this as a build step in a non-Python toolchain.

What I found

MVP2 asked a deliberately different question. MVP1 established that the alpha field is fixed; MVP2 asked what shape it is — can the field be regenerated from a geometric description instead of stored?

It can. The field turns out to be describable by 13 scalars, no matrix at all:

ParameterValueMeaning
center_x, center_y130.0, 154.5centre of the rounded rectangle
half_width, half_height111.5, 138.0half-extents of the content box
corner_radius5.25corner rounding
edge_softness1.0antialiasing width of the content edge
halo_gap9.0transparent gap before the glow starts
halo_sigma3.0Gaussian falloff of the glow
halo_peak72.09maximum glow alpha
content_alpha, alpha_floor255.0, 1.0opaque level, ambient floor

The interesting measured result is halo_gap = 9.0 with halo_sigma = 3.0. The glow is detached — it does not touch the picture. That gap is precisely why the effect reads as an ambient gradient rather than a stroke.

How I found it

This is inverse graphics: propose a parametric generator, then solve for the parameters that best reproduce the observation.

  1. Model the content region as a rounded-rectangle signed distance field (SDF) — negative inside, zero on the boundary, positive outside.
  2. Model the content edge as analytical coverage of that boundary, so antialiasing falls out of the maths instead of being sampled.
  3. Model the glow as a Gaussian in distance, gated to fire only outside the boundary and only beyond halo_gap.
  4. Fit all parameters per image, then aggregate with the median rather than the mean. That was a deliberate choice: the median is robust to the handful of samples with unusual edge antialiasing, which would otherwise drag a mean fit off the true geometry.
  5. Score the single aggregated model back against all 46 real alphas.

Formalization

Signed distance to a rounded rectangle, evaluated at pixel centres:

q_x = |x − c_x| − (h_w − r) q_y = |y − c_y| − (h_h − r) sdf(y,x) = ‖ (max(q_x,0), max(q_y,0)) ‖₂ + min( max(q_x,q_y), 0 ) − r

Content coverage — the analytical antialiased edge:

coverage(y,x) = clamp( 0.5 − sdf(y,x) / edge_softness , 0, 1 ) content(y,x) = content_alpha · coverage(y,x) · A_src(y,x)/255

The detached exterior-only Gaussian halo, which fires only where sdf ≥ halo_gap:

z(y,x) = ( sdf(y,x) − halo_gap ) / halo_sigma halo(y,x) = alpha_floor + (halo_peak − alpha_floor) · exp( −z² / 2 )

And the two layers combine by taking whichever is more opaque:

A_out(y,x) = clamp( max( content(y,x), halo(y,x) ) , 0, 255 )

Note that nothing here depends on 260 or 310 except the sampling loop. Change the canvas and the same formula renders a correctly proportioned frame.

Trade-offs

  • Tiny and legible. 13 named numbers versus 80,600 anonymous ones.
  • Resolution independent. The only genuinely scalable model of the three.
  • Editable by hand. Bump halo_sigma for a softer glow; raise corner_radius for rounder corners.
  • Least accurate. Assumes the designer's frame really is a rounded rectangle with a Gaussian shadow. It is close, but not exact.

Libraries — and alternatives

What I used

  • NumPy — mgrid to build the coordinate lattice, then vectorised hypot, maximum, clip, and exp to evaluate the SDF over all 80,600 pixels without a Python loop. This is the whole renderer.
  • Pillow — I/O only.
  • Aggregation used plain statistics.median semantics rather than a fitting framework, because each parameter is recoverable in closed form from the measured field.

If you want to do the same thing differently

  • SciPy — optimize.least_squares or curve_fit to fit all 13 parameters jointly by minimising residual against the real alpha, instead of recovering them one at a time. This is the natural upgrade path and would likely close some of the gap to MVP1.
  • Pycairo or Skia (skia-python) — production-grade vector renderers with native rounded rectangles and real Gaussian blur. Let the library rasterise the shape rather than hand-rolling the SDF.
  • Pillow alone — ImageDraw.rounded_rectangle plus ImageFilter.GaussianBlur gets you a visually similar frame in about ten lines, if you do not need an explicit parameter set.
  • SDFs in a shader — this maths is standard signed-distance-field work from the demoscene/GLSL world. Inigo Quilez's 2-D distance function reference is the canonical source for the rounded-box formula above, and the same code runs in WebGL, Shadertoy, or a Unity shader.
  • CSS — border-radius plus box-shadow expresses this exact effect natively in a browser, if the target is web rather than a PNG.

The leading term carries roughly 98 % of the spectral energy. In plain terms: the frame is almost exactly a product of one vertical profile and one horizontal profile, alpha(y,x) ≈ f(y)·g(x). That is a real structural fact about the artwork that neither earlier model exposed — and it makes sense in hindsight, because a rectangle with a symmetric shadow is inherently separable. Terms 2–8 exist only to correct the rounded corners and glow falloff, where rows and columns are not quite independent.

How I found it

Working without Python meant building the stack from the ground up.

  1. Probed the runtime. Node.js and .NET are installed; Go, Rust, and ImageMagick are not. Node won because its standard library ships zlib — the one thing you genuinely cannot hand-roll cheaply for PNG.
  2. Surveyed the input format before decoding it. Read the IHDR of all 46 files: 31 are 8-bit palette with tRNS (29 of them also carry an iTXt chunk), 15 are 8-bit RGBA, none interlaced. That told me exactly which decoder paths were required and which could fail loudly instead of guessing.
  3. Wrote a PNG codec (png.mjs) — signature check, chunk walk for IHDR/PLTE/tRNS/IDAT, inflateSync, then reversal of all five scanline filters including Paeth. Palette indices are expanded through PLTE/tRNS so everything downstream sees uniform straight RGBA.
  4. Measured cross-image agreement independently, arriving at the same mean std of 0.4022 — a useful cross-check that the new decoder agrees with Pillow.
  5. Fitted the factorization by alternating power iteration with deflation, then scored it against the 46 real alphas.

Formalization

Treat the mean alpha field as a matrix and approximate it by a sum of outer products of 1-D profiles:

Â = Σ_{k=1..K} s_k · u_k ⊗ v_k u_k ∈ ℝ^H, v_k ∈ ℝ^W, ‖u_k‖₂ = ‖v_k‖₂ = 1 Â(y,x) = clamp( Σ_{k=1..K} s_k · u_k(y) · v_k(x) , 0, 255 )

This is a truncated SVD written in separable form. Parameter count:

K · (H + W + 1) = 8 · (310 + 260 + 1) = 4 568 dense matrix = 310 · 260 = 80 600 → 5.7 %

Fitting without a linear-algebra library

Each rank-1 term is found by the fixed point that an SVD converges to. Starting from a uniform v, 120 sweeps of:

u ← R v ; u ← u / ‖u‖₂ v ← Rᵀ u ; v ← v / ‖v‖₂ s ← uᵀ R v

Then the term is deflated out so the next one fits the residual:

R⁽⁰⁾ = M R⁽ᵏ⁾ = R⁽ᵏ⁻¹⁾ − s_k · u_k ⊗ v_k

No BLAS, no LAPACK, no matrix library — just two nested loops and a normalisation.

Compositing, and the bug that shaped it

The first version multiplied source alpha by frame alpha directly. The idempotency check caught it immediately: re-applying the frame darkened the glow by up to 64 levels, because the glow gradient was being multiplied twice. The fix normalises away any frame the input already carries before re-applying:

A_content(y,x) = clamp( 255 · A_src(y,x) / Â(y,x) , 0, 255 ) (Â > 0) A_out(y,x) = Â(y,x) · A_content(y,x) / 255 RGB_out(y,x) = RGB_src(y,x) if Â(y,x) ≥ 128 (content) = (0,0,0) otherwise (black glow)

Max channel delta on re-apply is now 0 — exactly idempotent, not approximately. A fully opaque input yields A_out = Â; a fully transparent one stays transparent; a soft cut-out keeps its own gradient.

Trade-offs

  • Effectively matches MVP1's accuracy — median per-sample MAE 0.3470 against the dense template's 0.3326, a gap of 0.014 alpha levels — at 5.7 % of the parameters.
  • Runs anywhere Node runs. No install step, no native builds, no version conflicts.
  • Reveals structure. The near-rank-1 finding is genuine insight the other two models cannot express.
  • Largest file on disk (98,719 B) despite the fewest meaningful parameters — JSON text of 4,568 nine-decimal floats is verbose. A binary Float32Array dump would be ~18 KB.
  • Profiles are tied to this canvas. They can be resampled to another size, unlike MVP1's matrix, but that is interpolation rather than true resolution independence.
  • Hand-rolled codec. Correct for the inputs surveyed here; it deliberately rejects interlaced and 16-bit PNGs rather than mishandling them.

Libraries — and alternatives

What I used

  • node:zlib — inflateSync / deflateSync. The DEFLATE stream inside IDAT is the only part of PNG worth delegating.
  • node:assert/strict — the validation suite, no test framework needed.
  • node:fs, node:path. That is the complete dependency list.

If you want to do the same thing differently

For image I/O in Node — you almost certainly should not hand-write a PNG codec in production:

  • sharp — libvips-backed, by far the fastest; raw() gives you the pixel buffer and ensureAlpha() normalises channels. The standard choice.
  • pngjs — pure-JS PNG, closest to what png.mjs does, but handles interlacing and 16-bit too.
  • node-canvas — full HTML5 Canvas API server-side, so getImageData / putImageData work exactly as in a browser.
  • Jimp — zero-native-dependency alternative if compiling sharp is a problem.
  • Browser — OffscreenCanvas + ImageData needs no library at all.

For the linear algebra — power iteration was written by hand only because I wanted zero dependencies:

  • math.js — general-purpose, has matrix types and eigenvalue support.
  • ml-matrix — the direct fit: it ships a real SingularValueDecomposition class, so the whole of separable.mjs becomes a few lines.
  • numpy.linalg.svd or sklearn.decomposition.TruncatedSVD — the Python equivalents, one call each, if the no-Python constraint is lifted.
  • Eigen (C++) or nalgebra (Rust) — for a compiled implementation.
  • Going further — non-negative matrix factorization (NMF) would be a better fit than SVD for alpha data, since it constrains the profiles to be non-negative and so cannot produce the out-of-range values that the clamp here has to absorb.

Other runtimes available on this machine — .NET is installed, so System.Drawing.Common or ImageSharp with MathNet.Numerics for the SVD would have been an equally valid non-Python route.
